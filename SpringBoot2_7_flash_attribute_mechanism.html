Flash属性の仕組み図

RedirectAttributesとセッション管理による一時メッセージ保存機能
1
Controller処理：メッセージをセッションに保存
RedirectAttributesを使用して、メッセージをセッションに一時保存します。
通常のModelAttributeとは異なり、リダイレクト後も値が保持されます。
💾 Controller側の実装
@PostMapping("/students")
public String registerStudent(@Valid @ModelAttribute StudentData studentData,
                           BindingResult bindingResult,
                           RedirectAttributes redirectAttributes) {
    if (bindingResult.hasErrors()) {
        return "students/register";
    }
    
    studentRepository.save(studentData.toEntity());
    
    // 🔥 Flash属性でメッセージを保存
    redirectAttributes.addFlashAttribute("successMessage", "学生を登録しました");
    return "redirect:/students";
}
⬇️
2
リダイレクト：PRGパターンで画面遷移
Post-Redirect-Get パターンにより、フォーム送信後に別ページへリダイレクトします。
この際、Flash属性に保存されたメッセージもセッション経由で引き継がれます。
セッション管理の流れ
POST
フォーム送信
➡️
セッション保存
Flash属性
➡️
REDIRECT
302応答
➡️
GET
新しいページ
⬇️
3
View表示：セッションからメッセージを取得
ThymeleafがセッションからFlash属性を自動的に取得し、テンプレート変数として利用可能にします。
条件分岐により、メッセージが存在する場合のみ表示します。
🎨 View側（Thymeleaf）の実装
<!-- 成功メッセージ表示 -->
<div th:if="${successMessage}" class="alert alert-success alert-dismissible fade show">
    <i class="fas fa-check-circle me-2"></i>
    <span th:text="${successMessage}"></span>
    <button type="button" class="btn-close" data-bs-dismiss="alert"></button>
</div>

<!-- エラーメッセージ表示 -->
<div th:if="${errorMessage}" class="alert alert-danger alert-dismissible fade show">
    <i class="fas fa-exclamation-triangle me-2"></i>
    <span th:text="${errorMessage}"></span>
    <button type="button" class="btn-close" data-bs-dismiss="alert"></button>
</div>
⬇️
4
自動削除：表示後のメッセージクリーンアップ
Flash属性の最大の特徴：一度表示されると、メッセージは自動的にセッションから削除されます。
これにより、ページを再読み込みしても同じメッセージが再表示されることはありません。
Flash属性の自動管理機能
  • 一回限りの表示：メッセージは一度だけ表示される
  • 自動削除：表示後、セッションから自動的に除去
  • 重複防止：ページリロードでのメッセージ重複を防止
  • メモリ効率：不要なセッションデータの蓄積を防止

通常のModelAttribute

問題点

  • リダイレクト後に値が失われる
  • POST後の画面表示に制限
  • PRGパターンに対応困難

Flash属性

利点

  • リダイレクト後も値を保持
  • 一時的なメッセージ管理
  • PRGパターンに最適
  • 自動クリーンアップ機能
