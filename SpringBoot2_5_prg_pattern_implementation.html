PRGパターンの実装

🔄 Post-Redirect-Get パターン
重複送信防止と適切な画面遷移を実現する必須設計パターン
❌
直接レスポンス（危険）
フォーム送信後に直接HTMLを返す方式
@PostMapping("/students")
public String createStudent(...) {
    studentRepository.save(student);
    
    // 危険：直接HTMLを返す
    return "students/list";
}

// 問題：ブラウザ更新で重複送信発生
✅
PRGパターン（推奨）
POST後にリダイレクトしてGETで表示
@PostMapping("/students")
public String createStudent(...) {
    studentRepository.save(student);
    
    // 安全：リダイレクト
    return "redirect:/students";
}

// 解決：ブラウザ更新は単純なGET

🎯 Week 9.5 PRGパターン実装
@PostMapping("/students")
public String createStudent(@Valid @ModelAttribute StudentData studentData,
                          BindingResult bindingResult) {
    // バリデーションエラー時：同じページを再表示
    if (bindingResult.hasErrors()) {
        return "students/form"; // エラー時は直接表示
    }
    
    // データ保存処理
    Student student = studentData.toEntity();
    studentRepository.save(student);
    
    // 成功時：PRGパターンでリダイレクト
    return "redirect:/students"; // 一覧ページへリダイレクト
}
💡 リダイレクト先の設定ポイント
"redirect:/students" により、保存完了後は学生一覧ページに遷移。 これにより「登録 → 確認」という自然なユーザー体験を提供し、 ブラウザの更新ボタンを押しても単純なGETリクエストとなるため、 重複データ登録の心配がありません。Spring Bootが自動でHTTP 302レスポンスを生成し、 ブラウザが新しいURLにリダイレクトする仕組みです。
