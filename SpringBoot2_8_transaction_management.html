トランザクション管理図：@Transactionalによるデータ整合性確保の仕組み

🛡️ @Transactionalによる安全なデータベース操作

複数のデータベース操作をひとつの処理単位として管理
すべて成功またはすべて失敗を保証し、データの整合性を確保

⚗️ ACID特性：トランザクションの4つの基本原則
🔗 Atomicity（原子性）

トランザクション内の操作は
「すべて実行」または
「すべて取り消し」

部分的な実行は許可されない

⚖️ Consistency（一貫性）

データベースの制約・ルールを
常に満たした状態を維持

不正なデータ状態は作らない

🏠 Isolation（独立性）

同時実行される他のトランザクション
からの影響を受けない

並行処理でも安全性を確保

💾 Durability（永続性）

コミット完了後のデータは
システム障害が発生しても
永続的に保持される

🔄 @Transactionalプロセスフロー
✅ 成功パターン：自動コミット
@Service
@Transactional
public class StudentService {

    public void createStudent(StudentData data) {
        // 1. 学生データ保存
        repository.save(student);
        // 2. 履歴データ保存
        historyRepository.save(history);
        // 3. 通知データ保存
        notificationRepository.save(notification);
        // ✅ すべて成功→自動コミット
    }
}
  • 1️⃣ トランザクション開始
  • 2️⃣ 複数のDB操作実行
  • 3️⃣ すべて成功を確認
  • ✅ 自動コミット（確定）
❌ 失敗パターン：自動ロールバック
@Service
@Transactional
public class StudentService {

    public void createStudent(StudentData data) {
        // 1. 学生データ保存（成功）
        repository.save(student);
        // 2. 履歴データ保存（成功）
        historyRepository.save(history);
        // 3. 通知データ保存（エラー発生）
        notificationRepository.save(null); // 例外
        // ❌ エラー発生→自動ロールバック
    }
}
  • 1️⃣ トランザクション開始
  • 2️⃣ 一部のDB操作実行
  • ⚠️ 例外発生を検出
  • ❌ 自動ロールバック（取消）
📊 @Transactional有無の比較
❌ @Transactionalなし
public void createStudent(StudentData data) {
    repository.save(student); // 成功
    historyRepository.save(history); // 成功
    notificationRepository.save(null); // エラー
    // 結果：学生・履歴データは残り、
    // 通知データのみ失敗
    // ❌ データの不整合状態
}

⚠️ 問題：部分的な成功により、データベースが不整合状態になる

✅ @Transactionalあり
@Transactional
public void createStudent(StudentData data) {
    repository.save(student); // 成功
    historyRepository.save(history); // 成功
    notificationRepository.save(null); // エラー
    // 結果：すべてロールバック
    // ✅ データベースは変更前の状態を維持
}

✅ 安全：すべての操作がロールバックされ、データの整合性を保持
