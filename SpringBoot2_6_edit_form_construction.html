編集フォーム構築図

初期値設定・hiddenフィールド・更新専用UI - Week 9.6の中核技術

⚖️ 新規登録フォーム vs 編集フォーム

📋 新規登録フォーム (Week 9.5)
空の初期値でユーザーが入力、POSTメソッドでデータ作成
<form th:action="@{/students}" th:object="${studentData}"
      method="post">
    <input type="text" th:field="*{name}"
           placeholder="名前を入力">
    <input type="email" th:field="*{email}"
           placeholder="メールアドレス">
    <button type="submit">登録</button>
</form>
✏️ 編集フォーム (Week 9.6)
既存データを初期値として表示、PATCHメソッドでデータ更新
<form th:action="@{/students/{id}(id=${studentData.id})}"
      th:object="${studentData}" method="post">
    <input type="hidden" name="_method" value="patch">
    <input type="hidden" th:field="*{id}">
    <input type="hidden" th:field="*{version}">
    <input type="text" th:field="*{name}">
    <input type="email" th:field="*{email}">
    <button type="submit">更新</button>
</form>

🏗️ 編集フォームの詳細構造

編集フォームの5つの要素
ACTION
フォームアクション
対象レコードのIDを含むURL設計
th:action="@{/students/{id}(id=${studentData.id})}"
METHOD
HTTPメソッド
PATCHメソッドで更新操作を明示
<input type="hidden" name="_method" value="patch">
HIDDEN
隠しフィールド
ID・バージョン情報の確実な送信
<input type="hidden" th:field="*{id}">
<input type="hidden" th:field="*{version}">
INPUT
入力フィールド
既存データが初期値として自動設定
<input type="text" th:field="*{name}">
<input type="email" th:field="*{email}">
VALIDATION
バリデーション
Week 9.3のBean Validation継続活用
<div th:if="${#fields.hasErrors('name')}"
     class="text-danger">
    <small th:errors="*{name}"></small>
</div>

🔒 隠しフィールドの重要性

編集フォームに必須の3つの隠しフィールド
_method="patch"
ブラウザがPATCHメソッドを直接サポートしないため、POSTで送信しつつPATCH操作を指示
th:field="*{id}"
更新対象レコードのIDを確実に送信し、データベースの特定レコードを更新
th:field="*{version}"
楽観ロック制御用のバージョン情報を送信し、並行更新時の競合を検出
