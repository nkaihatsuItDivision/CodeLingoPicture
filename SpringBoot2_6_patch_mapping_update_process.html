🎯 @PatchMappingの詳細実装

Week 9.6における@PatchMapping活用
PATCH /students/{id}
@PatchMapping("/students/{id}")
public String updateStudent(@PathVariable Long id,
                           @Valid @ModelAttribute StudentData studentData,
                           BindingResult bindingResult,
                           Model model) {
    
    // バリデーションエラーチェック
    if (bindingResult.hasErrors()) {
        return "students/edit";
    }
    
    try {
        // StudentDataからEntityに変換
        Student student = studentData.toEntity();
        student.setId(id);
        
        // データベース更新
        studentRepository.save(student);
        
        return "redirect:/students";
        
    } catch (OptimisticLockingFailureException e) {
        // 楽観ロック例外処理
        model.addAttribute("errorMessage",
            "データが他のユーザーにより更新されています");
        return "students/edit";
    }
}

⚡ @PatchMapping更新処理フロー

1
リクエスト受信
PATCHメソッドで送信されたフォームデータを受信
PATCH /students/123
Content-Type: application/x-www-form-urlencoded
2
パラメータ取得
@PathVariableでIDを取得し、@ModelAttributeでフォームデータをバインド
Long id = 123L
StudentData studentData = form data
3
バリデーション実行
@Validアノテーションにより、Week 9.3のBean Validationが自動実行
if (bindingResult.hasErrors()) {
    return "students/edit";
}
4
Entity変換
StudentDataのtoEntity()メソッドでStudentエンティティに変換
Student student = studentData.toEntity();
student.setId(id);
5
データベース更新
JPA Repositoryのsave()メソッドでデータベースを更新
studentRepository.save(student);
// 楽観ロック制御も自動実行
6
リダイレクト
更新完了後、一覧画面にリダイレクトして成功を示す
return "redirect:/students";
// PRGパターンの実践
