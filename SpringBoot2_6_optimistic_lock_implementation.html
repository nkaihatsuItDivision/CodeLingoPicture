⚖️ 悲観ロック vs 楽観ロック

🚨 悲観ロック
データ読み込み時点でロックを取得し、他のユーザーのアクセスを完全にブロック
📋 特徴
✅ 確実な排他制御
❌ 処理性能の低下
❌ デッドロックリスク
❌ ユーザビリティ悪化
✨ 楽観ロック
データ更新時にバージョンをチェックし、競合があった場合のみエラーとして処理
📋 特徴
✅ 高いパフォーマンス
✅ デッドロック回避
✅ 良好なユーザビリティ
⚠️ 競合時の再処理要

🏗️ Student Entityでの楽観ロック実装

@Entity
@Table(name = "students")
public class Student {
    
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    @Column(nullable = false)
    private String name;
    
    @Column
    private String email;
    
    @Column
    private Integer age;
    
    @Column
    private Double score;
    
    // 楽観ロック用バージョンフィールド
    @Version
    private Long version;
    
    @CreationTimestamp
    private LocalDateTime createdAt;
    
    @UpdateTimestamp
    private LocalDateTime updatedAt;
    
    // constructors, getters, setters...
}

⚙️ バージョン管理メカニズム

@Versionアノテーションによる自動バージョン管理
1
初期データ作成
新規レコード作成時、versionは自動的に0に設定される
INSERT INTO students (..., version)
VALUES (..., 0)
2
データ読み込み
編集フォーム表示時、現在のversionも一緒に取得される
SELECT id, name, email, version
FROM students WHERE id = ?
3
更新時チェック
データ更新時、読み込み時のversionと現在のversionを比較
UPDATE students SET ..., version = version + 1
WHERE id = ? AND version = ?
4
競合検出
versionが一致しない場合、OptimisticLockingFailureExceptionが発生
if (updateCount == 0) {
    throw new OptimisticLockingFailureException();
}

🔍 競合検出と例外処理

OptimisticLockingFailureException処理フロー
🎯 バージョンチェック
JPA/Hibernateが自動的にWHERE句にversion条件を追加
⚠️ 更新件数確認
UPDATEの影響行数が0の場合、競合が発生したと判定
🚨 例外発生
OptimisticLockingFailureExceptionを自動的にthrow
🔄 例外ハンドリング
コントローラーでcatchし、適切なエラーメッセージを表示

💻 Week 9.6での楽観ロック実装例

StudentControllerでの楽観ロック処理
@PatchMapping("/students/{id}")
public String updateStudent(@PathVariable Long id,
                           @Valid @ModelAttribute StudentData studentData,
                           BindingResult bindingResult,
                           Model model) {
    
    // バリデーションエラーチェック
    if (bindingResult.hasErrors()) {
        return "students/edit";
    }
    
    try {
        // Entity変換・更新処理
        Student student = studentData.toEntity();
        student.setId(id);
        
        // 楽観ロック制御付きで保存
        studentRepository.save(student);
        
        return "redirect:/students";
        
    } catch (OptimisticLockingFailureException e) {
        // 楽観ロック例外処理
        model.addAttribute("errorMessage",
            "データが他のユーザーにより更新されています。
             最新データを確認してから再度実行してください。");
        
        // 最新データを再取得してフォームに設定
        Student latestStudent = studentRepository.findById(id)
            .orElseThrow(() -> new IllegalArgumentException(
                "Invalid student Id:" + id));
        
        StudentData latestData = StudentData.fromEntity(latestStudent);
        model.addAttribute("studentData", latestData);
        
        return "students/edit";
    }
}
🎉 楽観ロック実装による6つのメリット
⚡ 高パフォーマンス
読み込み時にロックを取得しないため、システム全体のパフォーマンスが向上
🔄 デッドロック回避
ロックの取得・開放がないため、デッドロック発生リスクを完全に回避
👥 優れたユーザビリティ
複数ユーザーが同時に編集画面を開けるため、使いやすいシステムを実現
🛡️ データ整合性保証
バージョン管理により、データの競合状態を確実に検出・防止
🏗️ 自動化された制御
@Versionアノテーションにより、複雑な排他制御を自動化
