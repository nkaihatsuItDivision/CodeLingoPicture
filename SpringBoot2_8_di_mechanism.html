依存性注入（DI）の仕組み図：@Autowiredによる疎結合設計の動作原理

🔗 Spring Boot依存性注入（DI）の威力

@Autowiredアノテーションにより、Spring Bootが自動的にオブジェクトを生成・注入
開発者は「何を使いたいか」を宣言するだけで、「どう作るか」はフレームワークが担当

📋 DI動作フロー：Spring Bootの自動注入プロセス
1
🚀 アプリケーション起動
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class);
        // Spring Boot起動時にBean管理開始
    }
}

Spring BootがApplicationContextを作成し、Bean管理を開始

2
📦 Beanスキャン・登録
@Service
public class StudentService {
    // @ServiceアノテーションによりBean登録
}

@Repository
public class StudentRepository {
    // @RepositoryアノテーションによりBean登録
}

@Service、@Repository等のアノテーションが付いたクラスを自動検出・登録

3
🔌 依存関係解決
@Controller
public class StudentController {
    @Autowired
    private StudentService studentService;
    // ↑ Spring Bootが自動で注入
}

@Autowiredを発見し、該当するBeanを自動的に注入

4
⚡ シングルトン管理
// Spring Bootの内部処理（イメージ）
StudentService service = new StudentService();
ApplicationContext.register("studentService", service);

// @Autowired実行時
controller.studentService =
    ApplicationContext.getBean("studentService");

1つのインスタンスを複数箇所で共有（シングルトンパターン）

❌ DI使用前：手動オブジェクト管理
public class StudentController {
    private StudentService studentService;

    public StudentController() {
        // 手動でオブジェクト生成
        StudentRepository repository = new StudentRepository();
        this.studentService = new StudentService(repository);
    }
}
  • ⚠️ オブジェクト生成ロジックが分散
  • 🔗 クラス間の強い結合
  • 🧪 テスト時のモック化困難
  • 🔧 設定変更時の影響拡大
✅ DI使用後：自動オブジェクト管理
@Controller
public class StudentController {
    @Autowired
    private StudentService studentService;
    // Spring Bootが自動注入

    // コンストラクタ不要
    // オブジェクト生成ロジック不要
}
  • ⚡ Spring Bootが自動管理
  • 🔗 疎結合設計の実現
  • 🧪 テスト容易性の向上
  • 🔧 設定一元化による保守性
